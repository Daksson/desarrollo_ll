Primero, lo que se ve

Una lista de 82 personajes y la ficha de cada uno

  • La lista. Muestra 10 personajes por página. Si escribo "sky" y le doy Enter, quedan tres: Luke, Anakin y Shmi Skywalker.
  • La ficha. Con "Ver detalle" voy a /starwars/1 y ahí salen los datos de Luke, su planeta y sus películas.
  • Cuando algo falla. Mientras espera dice "Cargando..." y, si la API no responde o el personaje no existe, lo avisa.
  • Y pruebas, para saber que no rompí nada cuando cambio el código.

Antes de meternos al código

Palabras que voy a repetir bastante

De la API
APIUn servidor al que le pido datos. En mi caso, swapi.dev.
Petición GETLa forma de pedirle datos. GET /people/1/ es "dame a Luke".
JSONEl formato en que responde: pares clave y valor, como "height": "172".
InterfazLe dice a TypeScript qué campos tiene un objeto y de qué tipo.
MapperMi traductor: convierte "172" en 172.
environmentDonde guardo la configuración, como swapiUrl.
Servicio / injectLa clase que habla con la API; con inject cualquier página la puede usar.
HttpClientLo que trae Angular para hacer peticiones: this.http.get(...).
expectOne / flushEn las pruebas: revisar qué pedí y responder con datos de mentira.
De Angular
ObservableUna respuesta que todavía no llega, pero va a llegar.
subscribe"Avísame cuando llegue". En next recibo los datos y en error el fallo.
pipe(map)Cambia la respuesta por el camino. Ahí llamo al mapper.
signalUna variable que, cuando cambia con set o update, actualiza la pantalla sola.
ComponenteUn pedazo de pantalla con su HTML, su CSS y su código.
input.requiredUn dato que el componente padre le tiene que pasar al hijo.
Ruta y :idQué página abre cada URL. :id es la parte que cambia, el 1 de /starwars/1.
routerLinkUn enlace que cambia de página sin recargar el navegador.
ActivatedRouteMe deja leer la URL actual, por ejemplo el id.
#searchInputUn nombre para el input, para leer lo que escribieron al dar Enter.
